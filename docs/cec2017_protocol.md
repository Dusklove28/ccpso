# CEC2017 问题适配协议

## 1. 29 函数协议与两套编号

本项目采用 CEC2017 的 29 个正式函数，排除原始源函数 F2。源 F2 在不同实现中存在定义不一致和数值不稳定问题，因此不进入本研究的问题集合。

项目对外暴露连续编号 `F1` 至 `F29`，同时在每个问题的正式元数据中保留原始 CEC 源编号：

```text
problem_id          项目连续编号 1..29
source_function_id  原始 CEC 编号 1, 3..30
```

映射规则为：

```python
source_function_id = (
    problem_id
    if problem_id == 1
    else problem_id + 1
)
```

因此项目 F1 映射源 F1，项目 F2 映射源 F3，依此类推，项目 F29 映射源 F30。源 F2 不可通过公开工厂访问。与原始论文、其他实现或外部实验结果比较时，必须同时报告 `problem_id` 和 `source_function_id`，不能把两套编号混为一套。

## 2. 类别、代表函数和维度

类别按项目连续编号定义：

| 项目编号 | 类别 | 数量 |
|---|---|---:|
| F1–F2 | unimodal | 2 |
| F3–F9 | multimodal | 7 |
| F10–F19 | hybrid | 10 |
| F20–F29 | composition | 10 |

本阶段固定四个代表函数：

| 项目编号 | 源编号 | 类别 |
|---|---|---|
| F1 | F1 | unimodal |
| F5 | F6 | multimodal |
| F12 | F13 | hybrid |
| F23 | F24 | composition |

正式维度仅为 `10、30、50、100`。即使第三方数据包含 2 维或 20 维数据，本项目也不把它们暴露为正式研究维度。所有问题采用逐维 `[-100, 100]` 边界，理论最优函数值为 `100 × source_function_id`。

## 3. 函数评价预算

正式主预算为：

\[
\mathrm{MaxFES}=10000D.
\]

`cec2017_max_fe(dimensions)` 只负责计算该协议预算，不会自动修改训练配置或实验预算。FE 敏感性实验只能作为辅助分析，不能根据最终排名反向挑选有利预算。

## 4. 组合函数精确移位点兼容

当前第三方 `cec2017` 包的源 F21–F30 在输入逐元素精确等于某个实际组合分量的官方移位向量时，会在组合权重归一化中形成 `inf/inf`，从而产生 `RuntimeWarning` 并返回 `NaN`。

适配层不修改第三方代码，只对源 F21–F30 做严格限定的兼容处理：

- 使用第三方包自带的官方 shift 数据；
- 只识别与实际使用的组合分量移位向量逐元素完全相等的输入行；
- 精确匹配第 `j` 个分量时返回 `optimum + 100 × j`，其中 `j=0` 为第一分量；
- 未精确匹配的输入仍原样调用第三方源函数；
- 不使用近似容差，不改变相邻浮点数；
- 不吞掉普通输入的非有限结果，也不屏蔽无关警告；
- 源 F1–F20 不应用该兼容分支。

各组合函数实际处理的分量数依次为：源 F21/F22 为 3，F23/F24 为 4，F25/F26 为 5，F27/F28 为 6，F29/F30 为 3。
